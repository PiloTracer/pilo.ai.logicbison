## Design judgments worth a conscious decision

- **D1 — fixed per-task cost, unvalidated.** Row 7 is mandatory for *every* task, and `standards/language/README.md` requires three lines in `Notes` even when nothing loads. A rename or a typo fix now pays a 71-line read plus three written lines. Phase 3's keep/drop procedure exists precisely to answer this — and all six ledger rows are `unmeasured`, with README admitting "This session did not run those pairs." Consider making row 7 conditional ("task edits code in a mapped language") or allowing a single `no card` line until the pairs are run.
- **D2 — "There is no cap" reverses the plan's token guard.** README:34 removes any limit; the plan's Phase 2 item 1 said don't inject all cards because "that fights the token budget" (`.cursorrules` Core Principle 9). Six cards × ~50 lines ≈ 325 lines if a broad task matches all six. The anti-trigger column is now the only brake. Possibly the right call — but it's a reversal, not an implementation, of the approved plan.
- **D3 — CHANGELOG precision.** "Each card has one **finished-code** example." The examples are sketches with undefined symbols (`fetch`, `Row`, `Body`, `Db`, imports omitted); optimization's is a text line plus a two-line function. "One worked example per card" is accurate.

## What's genuinely strong

- **The bidirectional guard is the best idea here.** The cards are forbidden from choosing a language (README:3, skill.md:164, anti-pattern list), and `plan-foundation/reference.md:503` records the reverse — cards are *not evidence* for `p2-backend`. That closes the obvious failure mode (an agent rationalizing a language switch from a concurrency rule) from both ends.
- **The anti-trigger column** ("`error` meaning 'the bug'", "`branch` as a git branch", "`public` as a word in a sentence") is exactly the right defense against keyword-driven context bloat, and it's specific rather than aspirational.
- **Epistemic hygiene:** dated `SOURCES.md` with per-page HTTP status *and* "do not treat this index as the page text"; `unmeasured` ledgers instead of invented results; `CON-PY5` pins the free-threading claim to a check date and marks the next release `unknown`; consumer `.work/standards/` explicitly wins on conflict.
- **Anti-bloat respected:** no new skill, no `.cursorrules` edit, and the plan's Reject table documents seven turned-down options with reasons — including "Editing the framework in the session that wrote this file."
- Cards are decision-shaped (default → if/then → reason → verify), which matches the feedback prescription the plan cites.
